## Phase A1 frontend preparation

- The API client has wrappers for officer queues, assignment, review start, decision, queries, notifications, admin analytics/users/audit logs, resources, and categories; all are consumed by their connected screens.
- `statusHelpers.js` maps the canonical API statuses to display labels and colors, with safe handling for unknown values. The status badge and timeline use this mapping while remaining compatible with existing mock display labels.
- The new-application mock flow retains all seven-step fields locally, shows save/submission feedback, prevents duplicate clicks, and does not generate a tracking number.
- The frontend `.env.example` already contains `VITE_API_URL=http://localhost:3005/api`; environment files are ignored by Git.
- Real applicant login, registration, logout, and session restoration use the backend; demo role login remains local. Startup profile/application flows and clarification response/resubmission use APIs for live sessions. Officer/admin review queues, review-start/decision, and clarification raise/list/resolve actions use the backend; admins can assign officers. Startup, officer, and admin notification screens use server list/read endpoints for API sessions. Demo application and notification flows remain local; document upload/verification is unconnected.
- The API application flow maps AYUSH labels to seeded category codes, stores regulatory/business fields in their JSON payloads, displays server tracking IDs and status history, and marks document actions unavailable where their APIs are not connected. Clarification screens use the query endpoints and retain mock behavior for demo sessions.
- `desk_App/main.js` launches Vite during development and serves the bundled website from Electron resources in packaged mode. The desktop experience inherits the current website's registration, live API, and demo role sign-in flows; it is not a separate authentication implementation.
- `desk_App/build-web.js` and `desk_App/vite.desktop.config.mjs` build the existing frontend into the ignored `desk_App/web-dist/` output without changing frontend source or writing Vite temporary config files into `frontend/`.
- `desk_App/package-desktop.js` runs electron-builder with build caches inside `desk_App/`. `npm run pack` assembled `desk_App/release/mac-arm64/AYUSH Setu Desktop.app` successfully on macOS arm64. `npm run dist:mac` produced a ZIP, but DMG creation failed because this environment's `hdiutil` reported `Device not configured`. Signing/notarization and actual GUI launch still need local user verification.
